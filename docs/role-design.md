# 内置角色设计与能力组合

四个业务角色和内置角色架构师的定义版本为 `1.1.1`，沿用原 ID、成员历史和私有经验关联。内置 Role 的显示名、章节标题、职责和方法，以及内置 Skill 的触发说明和正文使用英文。宿主使用英文组装岗位指令，回复与成果默认跟随用户请求的语言。中文岗位名保留为路由别名，旧版中文标题仍可导入。

## 岗位分别承担什么

| 角色 | 核心结果 | 主要方法与沟通 | 明确边界 |
| --- | --- | --- | --- |
| 产品经理 | 将真实问题转为可执行、可验收的产品决定 | 核对事实与假设，定义范围，咨询专业意见并解决矛盾；先说建议、依据和必要取舍 | 不自行编码，不将示例当事实，不代替专业验证 |
| 研发经理 | 基于真实仓库形成可运行、可维护的技术结果 | 区分咨询、设计与实现，先复现再修复，按影响验证；用具体文件和运行结果交接 | 不扩产品范围，不覆盖用户改动，不把构建当完整验收 |
| 测试经理 | 对具体版本给出可复现的通过、失败或未验证判断 | 按风险设计反例，检查实际产物，修订后复用相同反例；按严重性报告证据 | 不根据同事自述放行，不降低条件迁就缺陷，不推广到未检查产品 |
| 市场与营销负责人 | 提供真实需求与市场依据，形成准确价值表达 | 区分观察、转述、合成材料和推断，标注来源与时间，提出低成本验证；说明判断可信程度 | 不伪造访谈、数据或联网结果，不擅自联系客户、发送内容或承诺能力 |
| 角色架构师 | 根据实际工作配置能履职的角色及团队分工 | 优先复用成员，少量必要追问，选择方法与依赖，给出验证计划；体检引用具体配置与案例 | 不直接干业务工作，不擅自变更角色，不把文件存在当能力通过 |

岗位全文位于 [roles](../roles/README.md)与[内置架构师定义](../src/roles/role-architect.ts)。共同的主责、内部协作、旁听与正式发布权限仍由宿主控制；角色正文的动作边界不是操作系统沙箱。

产品经理默认使用读取和文档写入工具，运行命令与代码核查按需交给研发或测试。研发具有工作区读写与命令能力；测试保留运行验证命令；市场保留资料写入和调用已配置公开检索 CLI 的能力。工具声明不会自动配置外部检索或第三方集成。

## 从岗位描述到能力组合

架构师蓝图支持 `skills`、`mcpDependencies`、`communicationStyle` 和 `verificationPlan`。沟通与验证写入既有正文段落，沿普通创建、批量创建及事项提案应用保留，不新增用户维护的工作流。
验证计划支持简短文本或完整 `{ task, successCriteria, boundaryCheck }` 对象，宿主逐项保留到正文；缺失或不完整时显示尚未提供具体任务，避免静默回落后看起来已经具备验证方案。
这是候选配置提示，不是新增审批或生产语义门禁；角色能否胜任仍由实际任务结果判断。

`POST /api/members/design` 的规则模式与显式模型模式均保留用户给出的 `roleScope`、`roleId`、验证计划和额外约束。模型不能用自己生成的验证计划替换用户版本，也不能静默删除用户指定但尚未安装的 Skill；缺失项继续出现在能力报告里。架构师或设计模型还可输出可选的 `newSkills` 草案（限定 `role_local` 或目标作用域 Skill 库位置），草案仅返回给前端展示与勾选修改，只有在用户显式确认创建/导入/应用提案时才会原子落盘到 `<roleDir>/skills/<name>/SKILL.md` 或 `.data/skills/{global,orgs/<orgId>,users/<userId>}/`；创建角色仍然不会自动安装第三方依赖或启动外部服务。

宿主向架构师提供按调用者及目标作用域过滤后的能力声明与可用 Skill 目录。`role-design` 是其实际方法文件；架构师仍为零业务工具，宿主将该方法全文提供给无工具对话，并显式声明 Skill。普通业务岗位沿现有 `--skill` 装配，宿主在运行期校验所有解析后的 `SKILL.md` 真实路径（`realpath`）落在允许作用域根目录之内，缺失或越界路径会在启动模型 Worker 前报错。

候选方案的 `capabilityReport` 区分以下状态：

- Skill 的 `file_present` 只表示目标文件存在，`missing` 表示缺少文件。
- MCP 的 `runtime_check_required` 表示仅保留依赖声明，尚需执行时核查真实工具。
- 以上均不代表已完成任务。执行器继续按真实工具清单核查，创建角色不会安装 Skill、插件或启动外部服务。

候选卡片展示这些状态与验证约定；尚未提供图形化的 Skills 安装器或完整插件配置系统。共享模板继续保留完整职责正文，私有身份和工作经验不写入模板。

## 团队体检依据

体检仍按需发起，不新增定时后台扫描。宿主从当前配置、有限近期事项消息、负反馈和纠偏经验中形成有 ID 的材料；模型通过 `evidenceIds` 引用，宿主只接纳确实存在的来源并附带原始摘录。

卡片可展开查看来源并进入对应事项或团队页；未引用到来源时明确显示需核对。源记录证明曾记录什么，不自动证明模型的解释、因果判断或建议正确。旁听次数不称为有效次数，候选经验也不作为已经验证的事实。

## 配置更新与验证范围

启动时 `.data/roles/` 根目录及 `global/`（均归属 `global` 作用域，兼顾既有如 `ux-designer.md` 等全局定义）、`orgs/<orgId>/`（组织共享）与 `users/<userId>/`（个人私有）支持单文件 `<id>.md` 与带包内私有 Skill 的目录形式 `<id>/<id>.md`；同 ID 的全局定义仍优先于仓库基线，非全局目录不允许覆盖全局角色 ID，也不允许通过 frontmatter 伪造更高权限的作用域。需要更新自定义成员时，通过既有导入、团队管理或角色调整入口显式选择。

离线覆盖包括五个内置角色正文和边界的解析与序列化、英文指令进入 Worker、真实来源过滤、设计与导出字段保留、缺失 Skill 提前失败，以及宿主拒绝架构师发布。参见[能力测试](../test/role-capabilities.test.ts)和[编排测试](../test/phase2-orchestrator.test.ts)。

此前角色能力组合改动通过了 124 项离线测试、代码检查、构建与四种启动检查。使用临时数据库和受控方案在真实浏览器核对 1440px 桌面、390px 移动端，未见横向溢出。实际点击提案应用后确认 Skills 与 MCP 声明均保留。该页面检查不调用模型。

### 英文 Skill 小样本对照

此次对照发生在宿主提示和角色显示名切换为英文之前。在隔离的合成工作区，用 `kimi-for-coding` 的相同配置重复四次中文技术设计任务。每次使用独立数据库，无会话接续，只切换 `architecture-design` 的英文版与等义中文版。四轮都成功读取 `retry.ts`、用中文回复，原文件未变，未登记成果。英文配置的两轮均未观察到 Skill 正文读取，中文配置两轮中观察到一次。两组答复都出现了提交与崩溃顺序方面的歧义。样本不足以判断语言对方法选择或指令遵循率的影响。

## 2026-11-17：模型决策接口跟进

跟进 `5001069..fca5970` 后，为以下问题补充相同输入的离线回归：

| 问题 | 修订前观察 | 修订后检查 |
| --- | --- | --- |
| 用户指定角色配置丢失 | 指定 ID 被模型 ID 替换；验证计划与依赖路径存在丢弃分支 | ID、七条显式边界、用户验证计划和额外约束保留；未安装的显式 Skill 标记缺失，模型虚构 Skill 不进入草案 |
| 仓库读取证据误报 | 仅开放读取工具，没有调用也返回 `usedRepoRead: true` | 区分开放权限与实际读取；未调用、未完成、失败、越界及工作区外符号链接不算成功读取 |
| 校验器抛错未分类 | 普通异常漏出类型化决策接口 | 清理 Worker 后返回带原始输出与原因的 `validation_error` |

三个新用例修订前失败，修订后通过，另补 HTTP 层的用户计划/约束/依赖保留检查。完整 135 项离线测试、代码检查、构建、文档检查及四种启动检查通过；均使用临时资源，不访问已登记业务工作区。

同日执行一次真实 `npm run demo:decision`，4 个场景通过：人类先对齐、否定职责下的法务缺口、实际查仓后的研发牵头与定向旁听、模型角色草案。查仓记录包含 `README.md`、`package.json` 两个成功读取路径。原始报告保留于临时目录 `personal-agent-decision-I0TXEK/decision-report.json`。本次未做独立正文质量审阅，也没有修订前后的同题真实模型对照，不能将集成通过认定为岗位判断质量提升。

已增加 `demo:architect` 与 `demo:roles`，分别验证创建后履职与四个岗位的实际任务。[真实验证记录](role-design-demo.md)保留了初轮失败及同题修订后结果：结构化计划丢失已修复，业务岗位内容判断仍有失败，尚未证明整体能力改善。
后续回归共 130 项离线测试通过，代码检查、构建和四种启动检查通过；真实岗位内容失败仍作为独立结果保留，不计入离线机制通过结论。

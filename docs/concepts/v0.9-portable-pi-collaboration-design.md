# 0.9.x 便携 Pi 协作扩展设计（`board` + `delegation` + `roles` 下沉）

> **文档状态**：演进设计与里程碑追踪（面向 `0.9.x`，对应 [未来版本提案 P-0907](future-proposals.md#p-0907便携-pi-协作扩展家族board--delegation--roles优先级p1)）。依据「喂养而不自造（Influence by feeding, never by assembling）」与「顺着 Pi 纹理生长」原则，把 Lead（`delegate_to_member`）、Board（`spawn_board_agent` / `post_to_board` / `read_board_post`）与默认岗位定义下沉为彼此职责单一的便携 Pi 扩展包，通过**双后端适配器**同时服务原生终端 `pi` 与 Personal Agent 宿主。

---

## 1. 设计动机与三包职责划分

Personal Agent 的角色能力（[role-skills](../../pi-extensions/role-skills/README.md)）、Skill 目录（[skill-catalog](../../pi-extensions/skill-catalog/README.md)）、人工澄清（[human-question](../../pi-extensions/human-question/README.md)）、结构化卡片（[visualize](../../pi-extensions/visualize/README.md)）与下一步建议（[next-steps](../../pi-extensions/next-steps/README.md)）均已实现为可脱离宿主运行的 `pi-extensions/*`。在此基础上，协作侧拆分为 3 个独立可安装的便携扩展包（共用 [shared/local-rpc-worker.ts](../../pi-extensions/shared/local-rpc-worker.ts) 与 [shared/team-bridge-client.ts](../../pi-extensions/shared/team-bridge-client.ts)）：

1. **[pi-extensions/board](../../pi-extensions/board/README.md)（`pa-board`）**：仅负责 Board 异步协作原语（`spawn_board_agent`、`post_to_board`、`read_board_post` 与独立终端 `/board` 命令），保持与 PA Board 模式严格对齐；
2. **[pi-extensions/delegation](../../pi-extensions/delegation/README.md)（`pa-delegation`）**：仅负责 Lead 同步跨岗委托原语（`delegate_to_member`），PA 下复用组织花名册与资料空间预检，独立终端下按角色定义拉起隔离 `pi --mode rpc` 子进程；
3. **[pi-extensions/roles](../../pi-extensions/roles/README.md)（`pa-roles`）**：作为 4 个默认业务岗位 Markdown（PM / 研发 / QA / 市场）的**单一事实源**（根目录 `roles/` 仅保留 PA 宿主专有的 `pi-default.md` 与 `role-architect.md`，`loadRoleTemplatesFromDir` 自动合并两处），供独立模式下的 `delegation`、`board`（`sourceMemberId`）与 `list_roles` / `/roles` 按优先级解析（`PA_ROLES_DIR` → `<cwd>/roles` → `~/.pi/roles` → 包内置 `roles/`）；在 PA 宿主下自动让位于组织级多租户花名册（`read_team_roles`）。

### 核心设计约束

1. **工具契约唯一，不造两套插件**：模型在原生终端 `pi` 与 PA Web 工作台看到的工具名和核心参数语义完全一致，Prompt 与 Skill 方法论直接通用。
2. **双后端自动路由**：同一扩展入口自动识别 `PA_TEAM_BRIDGE_URL`——存在时走 `PaBridgeAdapter`（接入 PA SQLite、SSE、3 层看板、Space 与 CoE）；否则走本地持久化与直拉 `pi --mode rpc` 子进程。
3. **PA `solo` 模式默认保持纯净**：PA 工作台的 `solo`（`Pi Default`）轨道不默认注入团队协作工具 schema，避免干扰轻量单兵的低 token 边界；原生终端 `pi` 用户按需通过 `--extension` 或 `pi install` 显式组合挂载。
4. **模块边界硬约束**：`pi-extensions/*` 严格遵守 `scripts/check-module-boundaries.mjs` 规则，零 `@pa/*`、零 `packages/*` 与 `apps/*` 依赖。

## 2. 下沉边界与宿主职责分工

| 能力维度 | 便携 `pi-extensions`（`board` + `delegation` + `roles`） | Personal Agent 宿主（`packages/server` + `apps/web`） |
| --- | --- | --- |
| **定位** | 个人本机终端按需启动的多 Agent 协作与默认角色包 | 常驻服务、团队交付与组织级工作台 |
| **工具协议** | 同名工具 `spawn_board_agent` / `post_to_board` / `read_board_post` / `delegate_to_member` + `/board` / `/roles` | 通过 `pa-extensions/board`、`pa-extensions/delegation` 直接复用同一批 Pi 入口（`kind: "builtin-pi"`） |
| **运行与调度** | 插件内置轻量状态机与共用 RPC Runner，拉起 `pi --mode rpc --session ...` 子进程 | [board-runner.ts](../../packages/server/src/orchestrator/execution/board-runner.ts) / [delegation-runner.ts](../../packages/server/src/orchestrator/execution/delegation-runner.ts) + 租约锁 + `@monitor` |
| **状态与会话存储** | `.pi/boards/<id>/`（`members.json`、`posts.jsonl`）与 `.pi/delegations/sessions/*.jsonl` | SQLite 拆表（`matter_events` / `matter_board_*`）+ `worker_sessions` |
| **HITL 与可观测** | `ctx.ui.input` 终端即时交互 + `/board` / `/roles` 快照 | Web 3 层看板、SVG `@mention` 图谱、SSE 推送、卡片热切模型 |
| **团队与长期资产** | 本机单人文件系统与包内 4 个默认岗位定义 | 多组织 / ACL、自定义角色库、Git 资料空间（Space）、`team-health` + CoE RSI 证据闭环 |

## 3. 双后端适配器与安全硬边界

```text
模型调用 board (spawn_board_agent / post_to_board / read_board_post) 或 delegation (delegate_to_member)
                                      │
                        ┌─────────────┴─────────────┐
              PA_TEAM_BRIDGE_URL 已设置     PA_TEAM_BRIDGE_URL 未设置
                        │                           │
                 PaBridgeAdapter             Standalone Pi Adapter
          (createTeamBridgeClient POST)    (roles/loader.ts 人格解析 +
           → PA TeamToolBridge HTTP          .pi/{boards,delegations}/ +
           → SQLite / SSE / Web 看板)        shared/local-rpc-worker.ts)
```

### 运行时安全与硬不变量

即使脱离 PA 宿主独立运行，以下门禁仍由代码强制执行（不依赖提示词自律）：

1. **总控专属组队权**：仅 Root Coordinator 可调用 `spawn_board_agent`；子 Worker（`PA_LOCAL_BOARD_SUBWORKER=1`）禁止组队；委托子 Worker（`PA_LOCAL_DELEGATE_SUBWORKER=1`）禁止递归再委托。
2. **Verifier / 独立验收只读边界**：[local-rpc-worker.ts](../../pi-extensions/shared/local-rpc-worker.ts) 对 `boardRole === "verifier"` 或 `delegate_to_member` 携带 `verification` 时，从 `--tools` 剥离 `edit` / `write` 并叠加 `--exclude-tools edit,write` 双重隔离；Board 子 Worker 通过 `--tools` 显式放行 `post_to_board,read_board_post`。
3. **禁止自验证**：`LocalBoardStore.validateVerification` 在 `verdict === "pass"` 时拒绝作者验证自身或与 `authorAgentId` 相同的目标。
4. **增量游标懒加载**：每次唤醒 Board Worker 仅投递大于其 `lastReadPostNo` 的新板帖一行摘要；需要完整报告与证据时由成员显式调用 `read_board_post` 按需读取。
5. **异构模型透传**：`spawn_board_agent` 与 `delegate_to_member`（独立模式）均支持可选 `modelOverride`（`provider`、`model`、`thinkingLevel`），直接转化为子进程 `--provider` / `--model` / `--thinking` 参数。

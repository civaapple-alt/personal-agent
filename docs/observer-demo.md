# AI 成员旁听真实任务演示

`demo:observer` 用虚构的反馈箱设计任务，验证事项中点名旁听、后加入的背景接续、主动提醒、意见回到负责人、静默和关闭开关。调用正常的 `dispatchMatter` 与本机 Pi，不预制 AI 回复。

## 运行

在仓库根运行：

```bash
npm run demo:observer
npm run demo:observer -- --help
```

默认创建系统临时工作区、数据库和会话，不读取或改写 `.data/`、已登记业务仓库及原有演示事项。主负责人为产品经理，只选择测试经理旁听；研发经理在事项 AI 成员中，但本场景未被选中旁听，也未被要求委托。

共五轮主任务、三次旁听评估，均调用真实模型并消耗 token。模型配置来自仓库岗位模板，本次 thinking 设为 `off`，基础工具限定为 `read`。主负责人仍有正常团队工具，旁听模式禁用发布、委托与经验提案。只读工具配置不是操作系统沙箱。

## 任务链

| 阶段 | 任务 | 预期观察 |
| --- | --- | --- |
| brief | 旁听关闭，负责人记录删除后七天可恢复、不得清空原始来源 | 没有旁听执行；过程讨论不归档 |
| risk | 测试经理新加入；负责人只记录永久清空且不可恢复的待评审提案 | 新旁听上下文包含此前约束；测试经理主动指出冲突，作为独立发言留在对话中 |
| revise | 负责人结合真实旁听补充修订方案，并明确发布阶段 V1 | 意见进入负责人的接续上下文；只归档主负责人发布的阶段成果；旁听可按实际内容补充或静默 |
| quiet | 独立事项只修正通知中的人数 | 测试经理真实完成评估，返回静默标记，不在用户频道重复附和 |
| disabled | 关闭该事项旁听，再确认同一通知 | 没有新的旁听执行；主负责人仍正常回复 |

风险回合有意限制负责人原样记录待评审提案，以形成明确的旁听评审输入。`controlledRiskInput` 逐字核对提案正文，允许“已原样记录”之类的固定记录前缀及成对外引号，不接受额外分析或改写。失败表示本次受控刺激未按设计形成，不应据此断言测试经理缺少能力。这不是在宣称自然任务中的负责人必然遗漏风险，也没有指令让测试经理强制说某段答案。

当前旁听发生在主负责人一轮回复完成之后；它不是执行中实时插话或发布前质量门禁。主成果已成功提交后，旁听补充不会自动撤回成果或替负责人再发起一轮。演示通过后续明确用户消息让负责人继续处理意见。

## 看结果与证据

控制台打印临时目录，保留以下内容：

- `proof.db`、`sessions/`：实际消息、阶段成果与各自会话；测试经理在同事项两轮复用旁听会话，独立事项使用新会话，并与负责人分开。
- `evidence.json`：每阶段结果、Worker 模式、工具配置、原始回复、工具名称、会话与精简进程结果。不会保存桥接 token 或整份环境变量。
- `transcript.md`：完整受控输入、负责人回复、旁听原始回复及正式阶段文档。静默也保留在证据里，用户频道不新增静默发言。
- `quality-review.json`：针对本次对话快照的独立审阅模板，初始为 `pending`。
- `summary.json`：分开报告运行检查、旁听行为和独立质量结论。

运行检查包括：只执行选定岗位、后加入时收到前情、旁听意见进入负责人上下文、会话范围、受限工具配置、先主回复后旁听、正式成果只由负责人发布、初始资料保持与占用清理。没有发言不等于评估成功：空回复、模型失败或未执行不能算成功静默。

行为检查包括受控提案是否形成、风险回合是否实际插话、轻量任务是否真实评估后静默，以及关闭时是否不再调用旁听。插话存在不等于建议正确，正文质量仍须独立查看：是否针对七天恢复与来源约束，最终方案是否实际采纳有效建议，是否有无关补充或虚构验收结论。

独立审阅沿用[复核演示的记录格式](publication-review.md#查看证据)：保留正文哈希，填写审阅者、各标准 `pass/fail`、解释与行号原文引用，并记录新增阻塞问题。随后可离线刷新：

```bash
npm run demo:observer -- --summarize <证据目录>
```

帮助和离线汇总不调用模型。退出码 `0` 表示运行、行为及有效独立审阅均通过；`1` 表示运行/行为失败、审阅无效或质量失败；`2` 表示前两层通过但质量尚未审阅。模板未填写时返回 `2`，不会自动给岗位能力打分。

## 代码入口与验证边界

- [observer-case.ts](../src/demo/observer-case.ts)：虚构输入、五个阶段及独立审阅标准。
- [observer-runner.ts](../src/demo/observer-runner.ts)：隔离资源、真实执行与证据记录；不是生产旁听实现。
- [observer-evidence.ts](../src/demo/observer-evidence.ts)：运行/行为检查与离线审阅汇总。
- [observer-smoke.ts](../src/demo/observer-smoke.ts)：CLI 入口。
- [observer-demo.test.ts](../test/observer-demo.test.ts)：替换模型但保留编排、桥接、SQLite 和会话文件，检查接续、权限、静默与失败区分。

生产旁听路径在 [observer-runner.ts](../src/orchestrator/observer-runner.ts)。本演示不覆盖浏览器气泡渲染、运行中变更旁听席的界面操作或长期旁听稳定性；这些需要各自的验证证据。

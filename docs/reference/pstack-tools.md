# pstack 方法工具参考

本页说明 `load_pstack_skill` 的输入、输出、资源限制和岗位权限。安装和更新方法包请看[启用 pstack](../guides/pstack-runtime.md)。

## 装配与握手

执行器显式提供岗位 Skills、pstack 的模式入口和 [pstack-methods 扩展包](../../pi-extensions/pstack-methods/README.md)。PA 记录选定的方法包路径，Pi 管理包的安装与更新。个人版本机资源发现和其他模式的显式装配见[运行配置](configuration.md#cli-启动与能力装配)。方法工具必须通过实际工具清单握手，否则在业务提示执行前报错。

`runtime_ready` 通知记录外部清单声明的版本和模式正文 SHA256。该哈希只标识实际读取的模式正文。显式配置的包缺少模式、清单或必需方法时，执行会报错。程序还可通过 `TeamOrchestrator` 的 `pstackDir` 参数指定包。

## 方法读取参数

| 调用参数 | 返回内容 |
| --- | --- |
| `{}` | 当前包实际可用的方法名称和描述 |
| `{ "name": "poteto-mode" }` | 模式完整原文 |
| `{ "name": "poteto-mode", "resource": "playbooks/bug-fix.md" }` | 对应 playbook 原文 |
| `{ "name": "principle-fix-root-causes" }` | 原则的完整 `SKILL.md` |

每次成功读取返回原文、实际路径和 SHA256。模式与原则的 `disable-model-invocation` 元数据不会被误当成已经装载正文；本项目提供显式读取路径。实质任务先读取模式，再按任务选择方法。简单问候、确认以及没有实质风险的旁听不要求先装入完整模式。

本项目目前为 `poteto-mode` 的 `playbooks/bug-fix.md` 补充显式装载依赖：读取这个调试流程时，一并读取 `principle-fix-root-causes` 和 `principle-prove-it-works` 的原文，逐份返回路径及哈希。它解决实机中“选了流程却跳过原则”的问题，没有修改外部方法包；其他流程仍按需读取，不宣称已有完整依赖解析器。正文进入上下文不等于模型正确应用。

读取工具只接受包内有目录记录的方法和 Markdown 资源，拒绝越出 `skills/` 的路径与符号链接、非 Markdown 和超过 256 KiB 的文件，不执行附带脚本。它与岗位的通用文件工具分开，因此纯文稿岗位、无业务工具的角色架构师和旁听成员也可以读取方法，不因此获得读取业务文件或修改代码的权限。Pi 本身仍不是操作系统沙箱。

## 内循环服从实际岗位与宿主边界

- 主责、内部成员和旁听都可以使用方法；它们实际拥有的文件、命令和团队工具仍由原来的执行装配限制。
- pstack 提到专业协作时，使用当前事项允许的 `delegate_to_member`。它是已有岗位的咨询，不是任意子代理、外部 agent CLI 或工作树启动器。单兵模式仍没有委托工具。
- 主责才可发布正式阶段成果。内部成员不能发布，旁听不能委托或提出经验候选。方法包中的通用发布流程不改变这些宿主规则。
- 角色架构师启用后只有方法读取工具，仍没有业务文件、终端、委托、发布或经验工具。既有无 pstack 的零工具模式保持原行为。
- 包中的模型选择、会话扫描、自动化或分享建议不授予额外操作权限；模型与会话由本项目选择，普通交流不新增用户审批。

这一轮只接入正常岗位执行。独立的阵型 JSON 决策、快速角色设计模型和经验反思仍保持既有无工具隔离，不自动增加 pstack 上下文。没有实现完整第三方插件市场、依赖安装、任意子代理运行器或所有宿主工具的自动转换。

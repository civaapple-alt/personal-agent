# 不点名方法的主动选择验证

`demo:pstack:selection` 检查正常岗位执行时，用户不提 pstack 或具体方法名称，角色是否自行读取适合的模式和方法。它复用当前运行指引作为基线，不为通过验证预先加强方法路由。

## 执行方式与成本

```bash
npm run demo:pstack:selection -- --source /path/to/pstack
```

完整一轮包含五类任务、六次真实 Pi 主负责人执行，上下文恢复需要先记录决定再接续。它会消耗 Token。可以用 `--case how`、`why`、`teach`、`recall` 或 `architect` 单独选择场景；`--provider`、`--model` 可覆盖示例岗位的模型配置。

```bash
npm run demo:pstack:selection -- --help
npm run demo:pstack:selection -- --summarize /path/to/evidence
```

帮助和汇总不调用模型。执行产生 `run.json`、每项的原始 `turns.json`、`execution.json`、`transcript.md`、`rubric.json`、`quality-review.json` 及整体 `summary.json`。数据库、会话、项目和方法副本均保留在临时目录，不使用 `.data/` 或已登记业务仓库。

## 五类自然任务

| 观察目标 | 用户任务 | 检查的事实和边界 |
| --- | --- | --- |
| `how` | 接手反馈服务，解释一次提交从入口到缓存、保存和返回的路径 | HTTP 校验、用户/键组合、五分钟窗口、状态码、内存限制 |
| `why` | 追查为什么按用户区分重试、为什么是五分钟 | 实际提交前后代码、决策记录、数据依据与假设的区分 |
| `teach` | 为非程序员解释幂等键、重复点击和成功提示 | 用操作例子区分请求身份与相同正文，说明持久性边界 |
| `recall` | 找回先前决定，对照旧草案和当前代码 | 中文、12 人、800 元及暂不外接，与未批准的旧建议区分；真实 Pi 会话 ID 接续 |
| `architect` | 设计两个外部系统的可靠通知方案 | 模块、数据和状态、重试及超时不确定性、至少两种方案；不虚构已经实现 |

场景提示不包含目标方法名称、评分标准或使用 pstack 的要求。目标标签和审阅标准只写入执行工作区以外的证据目录。外层岗位指引仍然介绍 pstack，这是正常运行条件，不等于完全没有任何系统引导。

仓库包含真实创建的本地 Git 提交和据其生成的只读历史快照，全部业务数据为合成资料。方法源固定为本轮复制的包，逐文件留哈希。岗位仅有通用读取和既有团队工具；单兵执行不能委托，任务明确不发布成果。演示专用的 Pi 读取钩子限制为当前临时项目、自己的临时会话、方法副本和已批准岗位方法文件，拒绝读取操作者的真实会话或其他工作区。该演示读取边界不代表生产 Pi 已成为通用操作系统沙箱。

## 三层结果分别判断

1. **执行与完整性**：执行成功，项目和方法副本未变，没有正式交付；上下文场景确实接续相同 Pi 会话 ID。
2. **目标方法是否被观察到**：成功的方法工具结果含完整正文和哈希，或通用读取工具返回精确来源文件的完整正文。只提名称、只读目录、调用失败或只收到别的方法均不计入。
3. **回答质量**：单独审阅事实、取舍和适用边界。使用已有[带哈希和行号的审阅校验](../src/demo/publication-review-quality.ts)，逐项填写通过、失败及依据，保留新增问题。未审阅保持 `pending`，不以关键词或调用次数自动放行。

没有观察到目标 Skill，不直接等同于回答错误。某个任务可能采用其他合适方法，也可能在没有读取目标方法时给出准确结果。报告同时保留实际方法调用，便于判断这种差别。正文装载也不证明模型正确应用方法或产生了因果收益。

退出码：`0` 表示执行、目标方法观察和已审阅质量均通过；`1` 表示存在执行/质量失败、无效审阅或目标方法未被观察到；`2` 表示没有上述失败，但质量仍待审阅。看到 `1` 时需要查看分项，不能统一解释为业务任务失败。

单次每类任务只能提供样例证据，不能证明跨模型或长期稳定性。需要评估改善时，保留这一轮，再以相同任务和标准重复运行；不要删除没命中目标方法的记录或改写任务提示来掩盖缺口。

# 在工作台安排事项与验收成果

这篇指南供个人用户和团队成员日常使用。首次启动请从[安装与首次运行](../tutorials/getting-started.md)开始。部署服务、管理账号权限和备份数据请看[团队管理指南](team-administration.md)。

## 加入组织

使用团队工作台时，打开组织管理员发来的邀请链接，按页面提示注册或使用已有账号加入。若系统提示账号待审核，请等超级管理员通过后点击「刷新审核状态」。

浏览器已登录其他账号时，邀请页会提示是否继续使用当前账号。为新成员注册时，选择「退出并注册新成员」。

## 交办一件事

在新建事项中说明目标、已有资料、期望成果和约束。涉及文件时，选定组织和仓库。首次启动自动登记的 `personal-agent` 指工作台自身的源码仓库。

如果你在本机所有者模式下为已有仓库交办任务，Pi 会沿用你已启用的用户 Skills 和扩展，以及它信任的仓库 `.agents/skills` 和 `.pi/` 配置。带项目资源的仓库如尚无可信决定，可在该仓库的 Pi 中确认信任。 [本机资源配置](../reference/configuration.md#cli-启动与能力装配)

团队版普通账号需要先创建或加入组织。选定仓库时，事项沿用该仓库的组织。未绑定仓库时可以选组织，留空则使用自己所属的默认组织，或所加入的第一个组织。发起 Role Architect 对话时同样可以选择组织，仓库选择会隐藏。

可以用这段话开始设计讨论。

> 为小团队设计一个反馈收集盒。先读取已有资料，明确首版用户、范围和验收条件；产品经理牵头，必要时请教研发和测试。目前不编码、不提交 Git。形成可审阅方案后再发布 V1，过程讨论不归档。

发送前，在输入区顶部核对组织和仓库。用输入区左下角的 `+` 附加资料。

- 图片支持 PNG、JPEG、WebP 和 GIF，每次最多 6 张。也可以拖拽图片或按 `Ctrl/Cmd+V` 粘贴。
- UTF-8 文本与代码文件每次最多 6 个，单文件上限 512 KB。
- 直接粘贴达到 600 字符或 10 行的纯文本时，工作台将其折叠成附件。发送前可预览或选择「放回输入框」继续编辑。发送后从消息中打开附件。

信息不足时，可以先发起讨论，请负责人补齐关键问题。

## 在同一条对话里讨论和交办

在输入框写下消息，点击「发送」。点击「@角色」或直接输入 `@` 点名事项成员。点浮层外或按 Esc 关闭候选列表。

- 想和同事同步，直接发消息。普通同步消息会留在对话里。需要 AI 主动参与这类交流时，在「协作成员」开启「未点名时也让 AI 主动回应」。
- 想请 AI 回答，可以写「@QA Manager 这条验收标准清楚吗？」。被点名的角色可读取仓库资料来回答；没有点名的明确请求通常由事项负责人接住。
- 想让 AI 动手，可以写「@QA Manager 跑一下登录回归并记录结果」。明确交办会在权限允许时启动本轮执行，点名角色接手这轮，事项负责人仍负责后续。需要确认是否执行时，AI 在「待你决定」卡片给出「开始执行」和「先讨论」。没有派发权限的成员可以提交提请，由有权限的管理者审批。

AI 忙碌时仍能发送消息，发送后的提示会说明本条消息是否启动了新的处理。讨论回复与执行进度都留在同一条对话中。

新建事项时在「调整参与方式」选择负责人和团队范围。已有事项中，点开「协作成员」里的 AI 成员可修改两项设置。

- **允许主责委托**。主责实际把子任务交给这位成员时，系统才创建或恢复该成员的内部会话。
- **主责回复后主动检查**。正式执行结束后，系统并行启动已选成员检查风险。成员可以静默，发现实质遗漏时直接补充。主责失败或在检查前取消本轮时，系统跳过检查。

同一成员的委托和主动检查各用一条会话。想查当前分工，可以直接问「现在有哪些成员？」。[会话范围与接续](../reference/runtime-collaboration.md#会话范围与接续)

## 查看每轮团队委托

从发起消息下方的「本轮委托」打开交接公告板。公告板按发生顺序展示派发、回报和未完成记录。转派标注上游委托编号，回报标注对应的任务编号。点击链接可以回到原任务，正文可展开查看。

运行卡片上的「本轮协作路径」显示谁委托了谁，以及成员当前在做什么。打开「委托关系图」还可以查看本轮已完成的路径，点击其中一项可回到公告板。也可以通过事项右上角的「团队委托与事件」切换历史轮次，使用「定位消息」回到这轮的原始对话。旧数据的归属无法判断时，可从「历史记录 · 轮次未确认」查看。

要让另一位成员核验交付，在对话中明确交办，写明要检查的提交、仓库文件或本轮文档草稿，以及通过条件。主责可以把核验派给另一位已启用且可请教的成员。公告板会显示验收对象和版本、验收结论及证据。涉及其他成员的任务时，验收记录可以跳回原委托。对主动送审的文档，修改正文后需要复验，最终版本通过才会归档。

公告板和关系图可按委托分支、参与成员或「独立验收」筛选。运行中的成员连续约三分钟没有活动时，运行卡片会标出该成员和最后一次活动。正在等待用户、下游结果或运行工具的成员按对应状态显示。

## 延续、停止与修订事项

在原事项继续提问，系统按保存的成员、组织和工作区上下文接续确切 Pi 会话。修改负责人或工作区会改变上下文范围，不等于把所有旧模型历史搬到新范围。

选择「停止」取消正在运行的任务。执行期间可以调整参与、旁听名单和旁听开关。要再次派发或切换负责人和工作区，等当前轮结束。刷新页面可以查看当前状态。

失败后先保留错误和过程记录，处理原因再继续。丢失或损坏的 Pi 会话会明确报错，当前没有用户一键修复入口，也不会静默创建空会话冒充接续。停止或失败不保证撤销已经发生的文件或外部工具操作。

## 审阅成果并反馈

在**交付成果库**打开阶段成果，核对本版重点、正文、文件或服务链接，以及需要时展开的过程依据。普通问答和澄清不会因为回复长而自动成为交付物。

请求修订时，请指出版本、发现的问题和期望变化。

> V1 中处理状态只有待处理和已完成。V2 增加处理中，并说明与合并、重开、迁移及验收条件的关系。保留 V1，保存新文件；研发和测试有不同意见时先澄清，再发布最终方案。

在对应版本记录验收评级和意见，再在事项中继续提出修订要求。反馈保存、后续 AI 执行和经验提炼是不同操作；若界面提示“验收已保存、复盘未完成”，先确认已保存意见，不要把可选复盘失败当成验收丢失。

通过文件发布的文档会保存登记时的正文快照。审阅时，请核对该版本的规则和验收条件。若源文件在发布后有改动，请明确要求发布新版本。

交付物是服务链接时，打开链接检查访问状态。工作台重启后，需要重新启动本地预览。

## 调整岗位模型

先在运行工作台的系统账号下用 Pi 登录供应商。点击模型按钮打开浮层，可按供应商筛选，再按模型名称或 ID 搜索。

| 你要改变的范围 | 在哪里设置 |
| --- | --- |
| 当前事项的主负责人 | 在新事项中点派发按钮左侧的「选择主责模型」，选择供应商、模型和思考等级。使用自动匹配时，可保留「按自动匹配的岗位配置」。已有事项可在轮次结束后从同一位置调整。 |
| 角色架构师的独立对话 | 点击发送按钮左侧的「架构师模型」，选择模型和思考等级后点击「应用」。 |
| 本组织的某个岗位 | 在「我的团队 → 组织 → AI 角色」选择供应商、模型和思考等级，再保存。 |
| 整个服务的默认模型 | 超级管理员在「超管控制台 → 平台安全边界 → 全局默认模型」配置。选择「使用 Pi 默认」沿用服务账号的 Pi 默认。 |

实际顺序为事项主责覆盖、组织岗位覆盖、系统全局配置、服务账号的 Pi 默认。按需请教和旁听成员按各自的岗位配置执行。讨论中点名其他 AI 角色时，按被点名角色的配置执行。调整模型后，当前事项可以接续原有会话。

旧版角色包仍可导入。已有的组织模型覆盖随数据库保留。只写在旧角色包里的模型配置可按上表重新设置。

## 处理事项中的待决定问题

当计划需要你明确范围、验收条件或下一步时，主责 AI 可以在对话内提请决定。展开事项顶部的「待你决定」，跳到对应卡片。选择一个答案或自行填写，再点「提交答案」。卡片会记录答复人、时间和版本。

默认由事项发起人答复。事项发起人或组织管理员可从已参与事项的成员中指定答复人。其他成员可以在聊天中补充依据。AI 协作者会先把问题交回委托者，主责提请时会标出来源。旁听 AI 可以补充意见。

提交答案后，系统接续对应的 AI 轮次。如果事项还在运行，或者答复人没有派发权限，答案会先保存。具有权限的成员可在事项空闲时点击「继续执行」。续跑中断后可以用已保存的答案重试。已经提交的答案和待办在刷新或重启服务后仍可查看。

## 核验经验与扩充能力

在团队或成果的经验面板查看候选经验，核对来源、适用组织或仓库，再选择核验、编辑、忽略或替代。注入次数和评价计数只是追踪线索，不能证明经验提高了结果质量。

用角色架构师规划岗位，或手动导入定义。使用前核对职责、Anti-Jobs、Skills、工具和验证方式。

业务事项中可直接输入「按刚才的方案创建两个 AI 角色」。明确的建角色请求会由角色架构师在本事项内生成提案，业务主责继续负责原事项。需要补充信息时，在「待你决定」卡片中提交自己的答案，再查看架构师更新后的提案。回答澄清问题后，另行确认创建。

提案默认显示角色名称、职责摘要和实际工具。展开查看诊断依据、职责边界、验证计划或配套 Skill。用「本批角色可用范围」选择哪些人可以使用新角色，再决定新角色是否加入本事项。配套 Skill 在角色详情中单独勾选，保存位置在同一处配置。需要收窄工具时，可在确认创建前取消勾选。角色职责中的路径约定由角色遵循，工具仍以工作区权限执行。最后从最新提案确认创建。已生效的提案会显示确认人和时间。

| 角色范围 | 谁能创建和使用 | 存储位置 |
| --- | --- | --- |
| 平台通用（`global`） | 超级管理员创建，跨组织使用 | `.data/roles/`。根目录里的旧自定义角色沿用此范围 |
| 组织共享（`org`） | 组织管理员或超级管理员创建，成员在所属组织内使用 | `.data/roles/orgs/<orgId>/` |
| 个人私有（`personal`） | 活跃的普通成员也可按配额创建。只有创建者可以查看、使用和管理 | `.data/roles/users/<userId>/` |

快速创建角色或通过角色架构师设计岗位时，可以同时生成 Skill 草案。勾选要采用的草案，再编辑 ID、正文和位置。确认创建或应用提案后，工作台才将所选 Skill 保存到角色包的 `skills/<name>/SKILL.md` 或所选的全局、组织、个人 Skill 库。

需要在团队启用完整方法包时，请由管理员按[pstack 配置步骤](pstack-runtime.md)操作。

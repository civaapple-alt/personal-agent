# 工作台功能速查

这份速查随 PA 发布。事项中的 AI 可以按主题查阅。完整的界面操作见[用户指南](user-guide.md)。

## PA 与 Pi

PA（Personal Agent）是当前工作台，负责事项、角色协作与决定记录。Pi 是岗位的执行底座，负责连接模型、运行会话和调用工具。PA 通过 Pi 的 RPC 接口启动并管理岗位会话。

## 事项与派发

在输入框里直接提问、讨论或交办，不再区分“讨论模式”和“执行模式”。需要特定角色接话时用 `@成员`；点名只作用于本轮，事项负责人在「协作成员」里设置。

示例：「@QA Manager 跑一下登录回归并记录结果」或「登录回归需要覆盖哪些情况？」都由对应角色直接按自身职责和工具处理。事项运行中可用「停止执行」中止，也可以继续补充信息。

## 工作方式与执行

每个 AI 岗位在对话中直接使用自己配置的 `tools`、Skills、`read_pa_help` 和 Human Question（`request_clarification`），并保持同一条持久 Pi 会话连续工作：

- 你在提问、讨论方案或核对状态时，角色会直接回复或只读查证，不擅自改文件、提交或发布成果。
- 你的任务意图明确时，角色会直接按自身工具执行、委托协作或提交成果。
- 当范围、方案或高风险操作需要你拍板时，主责会主动调用 `request_clarification` 发出「待你决定」卡片，等你答复后再继续。

## 协作与旁听

未点名时由主责先回应。可以用 `@成员` 直接向同事或 AI 发消息（仅点名人类同事时不会触发 AI）。「AI 旁听」开启时，列席的协作 AI 可在本轮回应后补充重要发现。主责始终可以按当前配置委托，点名的 AI 也照常回应。「本轮委托」和「查看交接」显示本轮分工与回传。

示例：主责请 QA 核对验收条件，QA 把结论交回主责。若启用旁听，旁听成员可以在主责回复后补充遗漏的风险。

主责可查看事项内成员的职责、边界、配置的基础工具与 Skills，以及同事项、同工作区最近一次内部协作启动记录。角色声明和历史清单不代表下一轮一定能使用或成功执行；缺少记录时为未知。按任务所需能力和证据选择成员，只有需要验证时才委托试探。

## 待你决定

假设你安排 AI 做登录验收，范围还未定。AI 可以调用 `request_clarification` 发出一张卡片，问「只验证登录，还是也验证找回密码？」

1. 指定答复人点选「也验证找回密码」或直接输入答复，点击「提交答案」。
2. 卡片显示「已答复」，并记录答复人和时间。
3. 事项空闲且有权限时，AI 按选定范围继续。如果答案已保存但还未续跑，有权限的成员可以点「继续执行」。

顶部的「待人类决定」可以跳转到本事项等待答复的卡片。

在事项里问「给我一个待你决定的交互演示」，展开回复下方的「试用『待你决定』」，可以选择并提交一条示例答复。

## 角色与权限

可以从「角色架构师」开始规划，也可以在业务事项的「协作成员」里邀请它介入。AI 可以提出新增或调整建议。创建前要选择角色使用范围、核对职责和工具，再由有权限的人确认。需要为独立工作流新增岗位时，先说清楚负责什么、有哪些边界。

示例：说「帮我设计一个只做发布验收的角色」，会得到可审阅的提案。应用组织共享角色需要相应组织权限。创建角色和加入某个事项是两个选择。

## 成果与反馈

每个组织、仓库、人类用户、AI 角色以及自定义空间都拥有独立的 Git 仓库，事项关联其中的文档。私密事项默认使用发起人的个人空间；其他事项优先使用关联的工作区空间，没有工作区时使用组织空间，并非每个事项都有独立仓库。主责可以把计划和过程资料保存到当前事项默认空间，文档可按组织、仓库与相对路径关联业务仓文件或链接。从事项右上角的「⋯」打开「资料空间」，可查看本事项的空间资料；在左侧「资料空间」可切换空间、编辑文档并查看每次修改的 Git 提交历史与 Diff。经验复盘在事项协作抽屉的「经验复盘」中直接基于对话与空间资料执行。

打开文档的「版本反馈」，可以对当前提交填写评价和意见。选择历史提交后，可评价选中的版本；再次保存会更新本人对该版本的意见。

示例：保存第一版验收清单后，用户提出补充要求。主责更新文档，空间 Git 仓库会记录新的提交与完整 Diff。

## 模型、仓库与已开放能力

可以在输入框旁调整本事项的主责模型。组织岗位和平台默认模型由有权限的管理者设置。事项使用的仓库在事项设置中绑定或切换。

网页检索需要管理员安装并完成配置。pstack 等 Skill 包由服务账号通过 Pi 安装与启停。岗位这一轮实际可调用的工具以运行时工具清单为准。PA 当前通过平台配置、角色和 Skills 提供这些能力。Pi 插件可以在 Pi 中安装。向 PA 新增产品能力需要维护者开发及发布。

问「这个岗位能使用哪些工具和扩展？」可以查看岗位本轮或最近一次在本工作区启动时的工具清单。Human Question 扩展提供 `request_clarification`。主责用它向人提请决定，协作者用它向直接委托者澄清。

工具配置、启动时加载和实际调用结果是不同的证据。工具在清单中不代表凭据、网络或供应商正常；没有调用时应说明尚未验证。工具调用未报告错误也不代表返回内容质量已经通过审阅。普通协作者拥有 `bash` 时可能修改文件，即使没有 `write`；旁听和独立验收使用更窄的工具清单。Pi 以服务账号权限运行，不是操作系统沙箱。

使用 `fetch_content` 查阅 GitHub 时，事项事件会根据工具明确返回的标记说明是临时克隆、API 视图或获取方式未知，并标出已知的截断。临时克隆可能随岗位进程结束清理，不等于已登记的工作区；继续使用前应检查路径或重新获取。回答仓库问题时说明实际读到的文件、截断和已确认的版本，不把推测的代码数量或未检查的本机副本当作事实。

## 经验复盘

事项经验复盘可提炼角色协作和执行中可复用的方法。候选经验需要核验后才能作为已验证经验复用。查看内容时核对来源及适用的组织或仓库。

示例：某类验收反复漏掉回滚检查，可以提炼为候选经验，并用另一轮真实验收核验。

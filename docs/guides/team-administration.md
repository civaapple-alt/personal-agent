# 部署与管理团队工作台

这篇指南供部署工作台的服务管理员、超级管理员和组织管理员使用。团队成员接到邀请后可按[加入组织](user-guide.md#加入组织)进入工作台。

## 启动共享服务

在服务主机安装 Node.js、Git 和 Pi CLI，并为可用模型配置认证。安装步骤见[准备环境](../tutorials/getting-started.md#1-准备环境)与[配置 Pi](../tutorials/getting-started.md#2-安装本地-pi-cli-并配置模型)。服务通过宿主机用户权限访问文件和工具。部署前请确认[运行与网络边界](../../SECURITY.md)。

从源码部署时，在仓库根安装依赖并启动。

```bash
npm ci
PA_REQUIRE_AUTH=1 PA_HOST=0.0.0.0 PORT=4310 npm run start:web
```

使用预构建包时，在解压目录设置相同的环境变量，并运行 `node dist/server/main.js`。团队工作台默认将 Git 仓库克隆到数据库同级的 `team-workspaces/`。用 `PA_WORKSPACES_ROOT` 或超管控制台指定其他位置。

首次打开工作台时，在「初始化超级管理员账号」填写名称、邮箱和至少 8 位密码。自动化部署可用 `PA_ADMIN_EMAIL` 与 `PA_ADMIN_PASSWORD` 自举。初始超管凭证由部署者设置。

对外提供服务时，通过 HTTPS 反向代理访问，保留 `PA_REQUIRE_AUTH=1`。在同一主机部署反向代理时，可让工作台仅监听回环地址。使用管理员账号登录，确认侧栏出现「超管控制台」，再创建组织和发放邀请。

## 从个人本机试用切换到团队共享部署

1. 保持原数据库路径，再按[启动共享服务](#启动共享服务)中的命令启动。新版本会迁移现有数据库，保留组织、工作区、事项、成果、经验和会话关联。
2. 如果尚未设置密码，在首次访问时初始化超管账号。系统沿用占位账号 `usr_local_owner` 的 ID 及其组织身份。已设密码时，直接用原账号登录。团队模式下，本机回环访问也需要登录。
3. 在「超管控制台 → 平台安全边界」复查注册策略、克隆主目录、本地目录白名单和命令型预览。默认设置允许本地目录绑定和命令型预览。团队成员之间有信任边界时，关闭命令型预览。
4. 在「我的团队」新建业务组织，再给同事发送该组织的邀请链接。试用时登记的仓库和事项通常仍在默认组织。可将默认组织里的仓库设为「受限」，或将事项设为「私密」。
5. 迁往另一台服务器时，先停服并按[备份步骤](#保存与备份运行资料)收集运行资料，再核对目标机上的仓库路径。另开一份独立数据库时，使用新的 `PA_DB_PATH`。

旧局域网口令仍可加入协作，AI 派发使用正式账号。长期共享时使用邮箱账号和组织邀请。

## 团队账号、超级管理员与组织协作

超级管理员管理平台设置与用户审核。组织所有者和管理员管理团队成员、仓库权限及组织成果。

### 审核用户和设置平台权限

以超级管理员身份打开「超管控制台 → 平台安全边界」，设置注册策略、克隆主目录、本地路径白名单和命令型预览。默认设置允许本地目录绑定和命令型预览。

| 注册策略 | 用户如何进入 |
| --- | --- |
| 管理员审核（默认 `open_review`） | 用户注册后，由超管在「用户审核与配额」通过审核 |
| 自动开通（`open_auto`） | 用户注册后自动启用 |
| 邀请注册（`invite_only`） | 用户凭有效组织邀请码注册 |

在「组织与运行任务」可以中止异常任务。查看「安全审计日志」追溯操作。

### 创建组织并邀请同事

1. 在「我的团队 → 新建组织」按账号配额创建组织，选定所需 AI 角色。
2. 在组织卡片的「AI 角色」调整名册和主联系人。Git 默认沿用仓库的身份配置。若团队需要岗位署名，开启「AI 角色独立 Git Author 署名」。个人私有角色使用单独的 `maxPersonalRoles` 配额。
3. 以组织所有者或管理员身份打开「人类成员 → 组织邀请码」，选择成员身份，生成链接并发给同事。注册网址和登录流程见[加入组织](user-guide.md#加入组织)。

### 授权仓库、事项和成果

- 在「项目仓库与资料 → 登记项目仓库」输入 Git 地址，仓库克隆到 `<workspacesRoot>/<orgSlug>/`。选择组织内可见，或用「受限」名单逐一授权。已有事项、经验、执行历史或授权名单的仓库保留原组织归属。
- 新建事项时，在「调整参与方式」选择组织可见或私密。私密事项对发起人、所选人类成员及有权管理该组织的账号开放。普通成员可在授权和并发配额内派发任务，只读访客可查看授权内容。
- 成果库依据组织身份、仓库权限和事项范围筛选结果及预览。事项创建者、组织所有者、组织管理员和超级管理员可以修改成果访问范围。组织所有者和管理员可管理组织经验。

## 保存与备份运行资料

1. 停止服务和相关执行，再复制运行目录。默认复制完整的 `.data/`，包括 SQLite 数据库、会话、角色、Skills、附件和内置演示。
2. 如果设置了 `PA_DB_PATH`，另外保留数据库所在目录。Pi 会话默认仍在启动目录的 `.data/pi-sessions`，也可以用 `PA_SESSION_DIR` 单独配置。核对[实际存储路径](../reference/configuration.md#2-目录结构与默认存储位置)。
3. 保留外部工作区和配置单独指定的资源。迁移主机后，核对数据库中登记的仓库路径、新服务的启动目录和 Pi 会话位置。
4. 升级时用新版本打开原数据库，让应用执行增量迁移。迁移出错时保留错误并准备从备份恢复。需要回退时，使用与旧版本配套的升级前备份。

## 与同事在局域网协作

在可信局域网通过邀请口令临时协作时，扩大绑定范围，在「我的团队」管理内网协同成员并生成邀请链接。

```bash
PA_HOST=0.0.0.0 PORT=4310 npm run start:web
```

将终端列出的可达局域网地址和邀请链接发给同事。公网访问或长期团队协作请按[共享服务步骤](#启动共享服务)启动。

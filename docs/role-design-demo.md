# 角色设计与岗位履职的真实任务验证

`demo:architect` 验证从角色设计到实际履职，`demo:roles` 分别检查四个业务岗位。两者调用本机 Pi 与真实模型，使用独立临时工作区、数据库、角色文件和会话，不读取用户 `.data/` 或业务仓库。默认模型配置来自仓库模板。

## 执行与审阅

在仓库根运行：

```bash
npm run demo:architect
npm run demo:roles
```

- `demo:architect` 正常为两轮：架构师输出一个有方法、沟通与验证约定的只读发布审阅员蓝图；测试宿主沿现有提案 API 创建成员，该成员再实际读取文件、指出发布说明与版本及范围的矛盾。创建步骤代表场景中明确的用户选择，不新增过程审批。
- `demo:roles` 正常为四轮：产品梳理范围与验收，研发定位计数缺陷并做设计，测试实际运行失败反例，市场区分合成研究与待验证假设。每轮限定单兵处理，用于分别检查岗位判断，不能作为本轮多人自主协作的证明。

固定输入为虚构反馈工具：版本 `0.2.0`，发布说明却声称 `0.3.0`、云同步和自动合并；计数实现返回总行数 `3`，验收期望仅统计 open 行 `2`。研究材料明确是合成案例。测试指出该缺陷并报告失败，是岗位任务的正确结果，不是把应用验收判成通过。

不调用模型的入口：

```bash
npm run demo:architect -- --help
npm run demo:roles -- --help
npm run demo:architect -- --summarize <证据目录>
```

模型执行结束后默认保留独立审阅待办。由不属于被测 Pi 团队的审阅者阅读完整结果、角色定义及实际工具输出，在 `quality-review.json` 逐项填写通过或失败、说明和原文行号，也记录新发现的阻塞问题。审阅不得依据工具次数或版本数量替代语义判断。

| 退出码 | 意义 |
| --- | --- |
| `0` | 运行检查与全部独立质量审阅通过，且无新增阻塞问题 |
| `1` | 观察到运行或质量失败，或审阅无效 |
| `2` | 运行完成，独立质量审阅仍未完成 |

## 保留什么证据

- `workspace/`：完整固定输入，执行后核对所有非 Git 文件及新增文件是否改变。
- `proof.db`、`sessions/`：真实事项、提案、角色及确切 Pi 会话。
- `turns.json`、`transcript.md`：原始回复和实际工具调用；架构师结构化回复另外保留。
- `created-role.json`、`roles/`：架构师场景的草案、实际应用定义及 Markdown。
- `evidence.json`：场景与输入哈希、模板版本、检查结果及 Worker 能力声明。后续轮次还保留角色定义快照、Skill 文件哈希和上下文哈希；早期记录不补造这些历史字段。
- `quality-review.json`、`summary.json`：绑定原始文本哈希的独立审阅与离线汇总。

七项运行检查包括完整执行、预期轮次、工作区保留、零正式成果、无残留占用、声明能力范围及实际任务工具。文件和方法声明不代表内容正确。缺少外部集成时不测试或假装其可用；本场景没有验证外部 MCP。

运行器拒绝复用非空证据目录，不清空已有证据。默认 CLI 是真实 Pi；离线测试可以注入受控 Worker，证据须标记为 `controlled`，不能当真实岗位表现。

## 2026-11-17 同题前后结果

两条场景各执行初轮和修订后一轮，共 12 次真实主执行。独立审阅由本次 Codex 执行者在被测 Pi 团队之外完成，不使用该团队给自身打分。

| 场景 | 初轮 | 修订后 | 可支持的结论 |
| --- | --- | --- | --- |
| 架构师到新角色 | 运行通过；能力组合标准失败：模型给出结构化验证计划，宿主仅接收字符串，实际定义丢失具体计划 | 运行通过；三项定向标准通过，有非阻塞备注 | 修复解析后计划完整保留，新角色实际读取三份文件并指出矛盾；不证明该角色长期可靠 |
| 四个业务岗位 | 运行通过；产品、市场标准失败，研发存在额外阻塞问题，测试标准通过 | 运行通过；产品、市场仍失败，研发仍有核查范围过强问题，测试标准通过 | 增补定义与方法尚未证明岗位整体判断改善，不能把运行完成写成岗位质量通过 |

具体反例：

- 产品首轮改用未确认的 `V0.1` 且扩大待决问题；修订后问题收敛到排序，但仍引入 `V0.1` 和“不回退”状态约束。
- 研发两轮均正确复现计数错误并给出修复设计，但首轮未检索就声称无其他影响，修订后又声称六个文件全读及外部兼容性已确定，实际记录不足以支撑。
- 测试两轮均实际运行命令，报告期望 `2`、实际 `3` 和失败，并把未执行场景保持为未验证。
- 市场两轮均标注合成来源并给出假设，但仍把需求定义写成实际支持，修订后还混淆自动合并与自动归类的范围依据。
- 新审阅员两轮均发现版本及功能范围冲突；仍把发布说明未重复验收条款作为覆盖缺口，保留为非阻塞备注，未宣称所有语义判断正确。

# 验证 pstack 方法装载

本页供维护者复查真实模型是否读取了指定方法，以及脚本是否观察到预期行为。配置步骤见[启用 pstack](../guides/pstack-runtime.md)。

## 用真实任务检查装载和行为

```bash
npm run demo:pstack -- --source /path/to/pstack
```

`--help` 不调用模型；正常运行调用本机 Pi 与真实模型，会消耗 Token。脚本复制方法包的 Skills 到临时目录，创建独立数据库、会话和合成项目，不使用 `.data/` 或已登记业务工作区。

两个场景分别检查：

1. 产品经理实际读取指定的 `poteto-mode`，讨论尚未决定的到期行为，不提前产生正式交付。岗位现可使用通用文件与终端工具。
2. 研发经理处理倒计时函数的可复现缺陷。宿主先证明固定测试失败，角色再执行修复，宿主重跑同一份未被修改的测试。同时检查模式、根因与验证原则的成功读取记录，方法副本保持不变，普通过程没有正式成果。

证据目录保留 `report.json`、`proof.db`、Pi 会话、合成项目和方法副本。通过表示指定装载链路与确定性任务结果满足检查，不表示各岗位的语义质量、长期可靠性或方法带来的因果收益已得到证明。需要评估质量改善时仍须固定同题输入，重复运行并独立审阅。

离线回归见 [pstack-runtime.test.ts](../../test/pstack-runtime.test.ts)：真实资源读取、流程依赖正文、错误路径指引、路径与大小边界、目录查询、取消、架构师/旁听工具范围、静默以及缺失工具握手。它不调用真实模型。[证据判定](../../src/demo/pstack-evidence.ts)要求成功完成的方法工具结果同时含目标原文与对应哈希，仅提及名称、只有哈希、失败或未完成均不通过。

## 实机结果记录

2026-11-17 首轮证据目录为 `personal-agent-pstack-zB2VkP`。产品经理实际读取模式，但随后有一次原则路径调用失败；研发经理实际读取模式与修复 playbook，修复后固定测试通过，但未读取原则正文却在回复中引用原则，演示因此判定失败。该记录保留，不改为通过。

第二轮 `personal-agent-pstack-gBhUIT` 补充了正确调用示例、当前 Worker 成功读取清单及读取与应用的区别。模型没有再引用未读原则，固定测试也通过，但仍未装载原则正文，因此依旧失败。仅改指引未解决装载缺口。

第三轮 `personal-agent-pstack-tHxH7U` 在同一调试流程中显式装载两份原则依赖，两场景通过。再用同一套“完整原文＋哈希”判定器离线复核三轮：前两轮缺少原则正文，第三轮返回了实际正文与哈希。模式和方法副本保持不变，测试文件未被改写，没有正式交付。

三轮使用相同两项用户任务，共六轮主负责人真实执行。倒计时修复在三轮均通过固定测试，因此这次改善的是方法材料装载，不是已经证明修复质量提升，也不是模型自主选择原则已经稳定。产品对话只检查模式装载、工具范围和不提前归档，未作独立语义审阅。测试经理、市场负责人及旁听的真实任务表现仍未在本演示中验证。

本批 139 项离线测试、代码检查、构建、四种启动检查及文档检查通过；另直接调用构建后的方法扩展，确认能返回 playbook 与两份原则的原文、路径和哈希。构建检查与离线检查不新增模型请求。

上述早期任务中含有“按 pstack 方法工作”的提示，因此不能据此认定用户完全不点名时仍会主动选择方法。针对这一限制另补[五类自然任务验证](pstack-selection.md)，保留当前运行指引作为基线，并将目标方法观察和回答质量分别审阅。

# 验证会话接续、内部协作与经验记录

本页供维护者重跑协作与发布链路，并查阅有日期的实机记录。当前运行契约见[会话与协作参考](../reference/runtime-collaboration.md)。

## 可重复验证

运行以下命令验证代码、协议与构建：

```bash
npm run check
npm run build
npm test
npm run check:startup
```

可按下列行为选择回归。完整测试的入口和命令见[开发指南](../guides/development.md#选择验证范围)。

- 确切会话恢复、工作区与事项隔离、失败后接续。
- 真实扩展到桥接的调用、长耗时桥接免受 HTTP 300s `headersTimeout` / `requestTimeout` 中断。
- 同轮失败可重新委托、重复调用与委托边界、宿主桥接期间暂停空闲超时、子成员进度转发与轮次委托展示。
- 取消子树、阻塞对话关闭、连续多轮过程交流不归档、带变化依据的正式版本、内部成员发布权限、失败草稿丢弃、能力缺失与 HTTP 409。
- Phase 4 / 0.8.x RSI 与信任闭环：`propose_skill` 暂存与异常丢弃、旁听禁权、信任四步（`confirm` 弹窗确认 / 升级 `autonomous` / `disabled` 拦截）、确定性 `session-insights`、团队协作体检与 `space_document_feedback` 提交评价。
- 测试中的模型响应是受控 fixture，不据此宣称岗位能力或长期成长效果已经得到真实模型验证。

实机脚本使用服务账号的 Pi 配置调用模型，默认选择 Pi 已配置的模型。

```bash
npm run demo:team
# 或验证构建后的扩展路径与产物
node dist/demo/team-smoke.js
# 单独验证实际 Skill 沉淀提案与信任四步闭环
npm run demo:rsi
```

脚本验证过程与局限如下：

- 脚本在系统临时目录建立工作区、数据库、Pi 会话和证据文件。
- 第一宿主让产品经理咨询研发经理，为个人纯文本便笺工具讨论最小设计；随后继续一轮过程性澄清，两轮都不登记成果。
- 第二宿主以独立进程启动，恢复同一事项和 Pi session，回忆口令、研发证据及 IndexedDB 选择，再用实际成果工具归档简短设计测试稿。
- 场景中的假设不代表用户业务需求，脚本不访问已登记业务项目。
- 证据目录包含 `first.json`、`restart.json`、`proof.db` 与 `sessions/`；脚本退出时输出 PASS 或报错，并保留临时证据以便查看。
- 查阅下方实机记录，核对运行范围和留存证据。

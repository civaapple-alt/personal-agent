# 连续上下文与内部角色协作

这份说明描述当前生产路径。Personal Agent 使用本机 Pi CLI 1.5.2，保持现有 SQLite、角色 Markdown 与双栏工作台格式。岗位能力的长期成长、持久后台工作与公开人才市场仍未实现。

## 从用户消息到结果

新事项可指定成员，否则使用初始关键词路由，未匹配时交给主要联系人。后续消息默认由事项原负责人处理，保留已绑定工作区。成员通过 `delegate_to_member({memberId, task})` 决定需要谁的专业工作，`task` 应包含目标、必要事实、约束与期望结果。成员名单来自实际注册的团队，四个初始角色没有写死在委托逻辑中。

执行器每轮启动独立 Pi RPC 进程，但使用持久会话接续。Pi 注册的团队工具通过本轮专属的 loopback HTTP bridge 调用编排核。委托者、事项、工作区和调用链由宿主绑定，模型不能在参数里改写身份或跨事项寻址。子成员的工具循环完成后，答案作为真实工具结果回到委托者；请求、答案与错误进入 `internal_collab`，工具事件、运行能力清单进入 `notice`。子成员不会向用户频道流式输出，但运行期会将同事进度与 `collabUpdated` 转发给主进度流供工作台即时展示，主联系人负责整合结果。

涉及缺失信息的 Extension UI 对话仍由 DialogBroker 转交用户。普通产品澄清也可直接回复并等待用户下一条消息，无需伪造交付。

## 各模块的所有权

| 模块 | 负责的行为 |
| --- | --- |
| `TeamOrchestrator` | 事项负责人、工作区、运行所有权、委托树、用户回复与成果收尾 |
| `execution-context.ts` | Skill 路径解析、保存会话的身份验证、交付文件与 URL 验证 |
| `team-extension.ts` | 在 Pi 内注册模型工具、装配工具清单、加入当前岗位系统提示 |
| `team-tool-bridge.ts` | bearer token、请求解析、大小限制、调用 ID 去重、连接取消与清理 |
| `PiRpcWorker` | JSONL RPC、确切 session 启动参数、流式事件、settled、模型错误与进程退出 |
| SQLite store | 会话映射、消息、成果版本、原子批量归档与事项执行占用 |

选择独立工具 bridge 是为了保留真实的模型工具调用及返回值。用 `confirm` 对话夹带内部委托会混淆用户确认；直接扩展 Pi stdin RPC 命令则要求修改 Pi 协议或上游。因此 bridge 只承担工具调用传输，执行策略归编排核所有。

## 会话范围与接续

新会话的查找键由事项、成员、工作区 ID、绝对路径和用户/内部会话模式组成。后续轮次把保存的 `sessionFile` 传入 `--session`，不使用 `--continue` 或目录内最近文件。启动前校验 Pi JSONL 首行的 session ID 与真实 `cwd`。保存文件缺失、损坏或属于另一工作区时直接报错，不悄悄创建空会话。

每轮通过 `before_agent_start` 更新当前岗位五个定义段落、团队名单、工作区约束和适用私有记忆。系统规则不会反复塞进用户消息。Pi 的原生会话树负责模型历史与压缩；这里没有无限拼接完整对话。

首次交接给某成员或在其他成员处理后返回时，宿主最多补充 12 条、20,000 字符的同事项同工作区新增用户频道背景。会话记录中的 `message_cursor` 避免每轮重复加入历史。同成员连续追问直接依赖 Pi 原会话。背景只补充尚未进入当前会话的交流，委托方仍需在任务中给出相关决策和约束。

公司与项目私有记忆均需明确绑定工作区才能自动注入。无工作区的旧公司私有记忆继续保存并可查看，但不会在所有项目执行中加载。`role_general` 用于用户明确保存的通用岗位经验。尚无组织 ID，不能推断两个不同工作区属于同一公司，也不能自动跨工作区共享公司背景。

切换工作区后使用另一条会话，切回原工作区时恢复其原会话。即使同一个工作区登记后来改了路径，旧会话也不会被移到新目录执行。事项负责人变更会更新事项记录；切回原成员时恢复该成员的会话并补充有界的新交流。

`--no-session` 模式不打开历史 Pi 文件，只用上述有界背景，因此不具备完整的跨进程模型记忆。

## 兼容历史数据

数据库启动时只添加 `worker_sessions.context_key`、`message_cursor`、`matters.observer_ids_json`、索引及事项执行占用表，不重写消息、交付版本或原型。旧 session 映射按同事项、同成员、同工作区查找最后的文件，仍须通过 Pi 首行身份与路径验证；下一轮生成新范围的映射。

旧消息没有可靠工作区标记时保留供用户查看，但不会整体回放到其他执行现场。旧版每轮新建会话造成的历史割裂无法无损还原；迁移只能接回最后匹配的实际 Pi 会话。旧会话自身保留的历史规则和背景也不会被事后清洗。历史会话丢失时需恢复对应文件，当前尚无自动修复或用户一键重置入口。

## 能力装配与核查

角色 `skills` 中的名称解析到仓库 `skills/<name>/SKILL.md`，也支持绝对文件路径或相对角色文件的路径。初始 13 个声明均有实际 Pi Skill 文件，并通过显式 `--skill` 装载。缺失 Skill 会在模型请求前失败。分享角色定义不会把私有记忆打包，也不会自动安装其引用的 Skills 或插件。

默认关闭 Pi 自动扩展和 Skill 发现，显式加载团队扩展、角色 Skill 以及运维者在 `PA_PI_EXTENSIONS` 中批准的扩展路径。角色 `tools` 加上委托工具形成实际工具清单；直接负责用户交流的主成员还装配成果发布工具。内部成员不能直接发布用户成果，宿主也会拒绝伪造的发布请求。`mcp` 只是历史声明分类；具体 MCP 需求由 `mcpDependencies` 的服务器名指定，使用现有 Pi 配置。

MCP 或自定义扩展可能异步注册工具。团队扩展最多等待 10 秒，再从 Pi 的真实工具注册表筛选所需工具；宿主核查每个普通工具及每个 `mcp__<server>__*` 前缀。缺失能力会明确失败，不能靠提示词声称已具备能力。外部扩展与 MCP 的运行兼容性仍须针对实际配置验证。本轮实机验证没有使用外部 MCP 服务。

初始市场角色使用 `read`、`bash`，不再声明未实现的 `web_search`。可用 CLI 或公开页面访问不等于完整搜索服务，研究覆盖范围仍需说明。

## 并发、失败与停止

同一事项同时只有一轮用户执行。进程内运行表与 SQLite 执行占用共同避免两个宿主恢复同一会话。占用记录包含宿主 PID；宿主不存在时，下次显式请求可回收占用。此机制面向单机服务，不是分布式租约，也未防御操作系统 PID 复用。

不同事项可同时执行。一个委托树内，同一成员的同范围会话同时只允许一个执行者；忙碌目标返回工具错误。每轮最多 8 次不同委托，调用链最多 3 名成员，禁止调用自身或祖先。相同委托者、目标和任务在同轮复用结果；相同 transport call ID 和参数只执行一次，ID 对应不同参数时拒绝请求。失败也返回给委托方，由其决定如何继续；不会让用户处理每个内部错误。

停止信号传递到主成员、同事及桥接请求。子工具连接关闭只取消该委托子树。宿主执行桥接工具（如 `delegate_to_member`）阻塞父 Pi 进程期间，父 worker 通过 `suspendIdleTimeout()` 暂停自身 `idleTimeoutMs` 无活动超时，同时扩展侧通过 `node:http`、桥接服务侧关闭默认 300s `requestTimeout`/`headersTimeout`，使跨过 5 分钟的真实子委托不会被 HTTP 传输层误掐断，改由子 worker 各自的 `idleTimeoutMs` 与整轮总上限 `timeoutMs` 守卫；单次委托失败后会从本轮成功去重表移除，允许调用方同参数重试。超时属于未完成错误；用户主动停止生成停止回复。启动失败、阻塞对话、模型错误和进程异常均会进入清理路径。服务关闭先停止接收请求、取消对话，再等待整个执行树退出后关闭数据库。

HTTP 对同事项重叠消息以及执行中切换工作区返回 409，当前没有运行中 steer 交互。停止、失败或宿主重启后，下一条用户消息明确发起接续；不会自动继续未完成动作。

去重范围是本轮内存中的工具调用。硬崩溃后重试模型仍可能再次执行外部动作，没有全局 exactly-once 保证。执行器已经写出的文件或对外操作不会因取消自动回滚。

## 成果归档

主成员仅在形成可审阅的阶段成果、用户指定版本或实质变化时，调用 `publish_deliverable({type, title, content, changeNote, summary?})` 显式登记成果。`changeNote` 必须说明本版本的变化及依据，归档在成果摘要中；回复元数据关联成果 ID 与来源用户消息。普通回复、需求澄清、过程进度和细小调整只留在对话，不依赖回复长短、对话轮数或逐次人工批准来判断。

支持以下成果类型：

- `document` 使用完整、非空的正式正文。
- `artifact` 和 `prototype_image` 使用工作区内已存在的实际文件，路径检查解析符号链接并拒绝工作区外文件。
- `service_url` 使用 HTTP 或 HTTPS 链接。语法校验不代表链接可访问、服务仍运行或业务已验收。

内部同事与旁听同事都只从本职专业角度给出判断，不直接发布用户成果（旁听模式下工具装配与宿主桥接同时禁用 `publish_deliverable` 与 `delegate_to_member`）。每轮主成员回复成功后，列席的旁听成员在各自独立的 `observer` 范围会话中并行快速审视本轮对话：若无实质风险或增量则仅输出 `[SILENT]`（不写入对话流），确有关键风险或遗漏时以对应成员头像与「旁听补充」气泡直接发言到主对话流。主成员负责整合并判断是否达到正式交付条件。主成员登记的成果先暂存；整轮取消或失败不归档草稿。成功收尾时再次核查全部文件，再在同一 SQLite 事务中写入成果与版本。相同事项、标题形成版本系列。已有 API 调用方显式提供 `deliverableTitle` 时，仍可导出本轮非空文档回复；默认聊天不导出。工作台已移除根据“修改”前缀强制导出的旧逻辑，“继续修改”只提供对话上下文，不强制生成版本。

本轮成功且有正式成果时才标记 `delivered`，只有聊天、澄清或空正文时保持 `open`。这是归档状态，不代表用户已经验收。文档是否达到专业质量、实际文件是否正确、服务是否符合需求，仍需要具体证据和用户反馈。

## 可重复验证

运行以下命令验证代码、协议与构建：

```bash
npm run check
npm test
npm run build
npm run check:startup
```

当前 37 项回归包括确切会话恢复、工作区与事项隔离、失败后接续、真实扩展到桥接的调用、长耗时桥接免受 HTTP 300s `headersTimeout`/`requestTimeout` 中断、同轮失败可重新委托、重复调用与委托边界、宿主桥接期间暂停空闲超时、子成员进度转发与轮次委托展示、取消子树、阻塞对话关闭、连续多轮过程交流不归档、带变化依据的正式版本、内部成员发布权限、失败草稿丢弃、能力缺失和 HTTP 409。测试中的模型响应是受控 fixture，不据此宣称岗位能力已经得到真实模型验证。

实机脚本另行使用现有 Pi 配置调用模型，默认 `kimi-coding / kimi-for-coding`，不会输出密钥：

```bash
npm run demo:team
# 或验证构建后的扩展路径与产物
node dist/demo/team-smoke.js
```

脚本在系统临时目录建立工作区、数据库、Pi 会话和证据文件。第一宿主让产品经理咨询研发经理，为个人纯文本便笺工具讨论最小设计；随后继续一轮过程性澄清，两轮都不登记成果。第二宿主以独立进程启动，恢复同一事项和 Pi session，回忆口令、研发证据及 IndexedDB 选择，再用实际成果工具归档简短设计测试稿。场景中的假设不代表用户业务需求，脚本不访问书架项目。

证据目录包含 `first.json`、`restart.json`、`proof.db` 与 `sessions/`。脚本退出时输出 PASS 或报错，并保留临时证据以便查看。最终实机验证结果与证据目录见本轮交付报告。此证据覆盖一次有限的真实协作和接续，不代表多日自主工作、长期学习或外部服务可靠性已验证。

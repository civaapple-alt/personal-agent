# 完成四步内置演示

用虚构的「小团队反馈收集盒」走一遍需求讨论、专业协作、首次交付和修订。完成后，你可以在成果库打开同一成果的 V1 和 V2，查看反馈和变化依据。

## 打开与体验

从[首次运行](getting-started.md)启动工作台并配置 Pi。以本机所有者身份进入「新建事项」，点击「体验内置演示」。工作台会准备独立的示例组织、事项和 Git 工作区。发送提问后才使用模型额度。

1. **讨论需求。** 在「需求讨论」点击「填入提问」，检查文字后发给产品经理。等待产品经理根据背景和虚构访谈提出关键问题。
2. **请教研发和测试。** 在「专业协作」填入范围确认并发送。展开过程记录，确认研发经理和测试经理都回复了主负责人。前两步的内容留在事项中。
3. **查看 V1。** 在「阶段交付」填入并发送发布要求。等待产品经理保存方案并发布「反馈收集盒 · 产品方案」。在成果库打开 V1，核对归档正文和方案文件。
4. **给出反馈并查看 V2。** 在「反馈修订」点击「记录反馈并填入修订要求」，检查文字后发送。引导会保留已有的 V1 意见和验收评级。没有文字意见时，会记录一条标注为虚构情境的示例反馈。在成果库对比 V1 和 V2，确认修订内容和历史版本都可查看。

「已有记录」表示工作台找到了对应消息、委托、成果或反馈。若缺少委托或成果，在对话中请主负责人补齐。最后核对方案的依据、规则和验收条件。演示交付的是设计文档，示例反馈来自虚构情境。

## 工作区与保留规则

默认工作区是启动目录的 `.data/inner-matter/`。背景材料保存在 `docs/`，实际生成的方案文件保存在 `deliverables/`。演示有自己的 Git 工作区，Pi 仍以服务用户的系统权限运行。

再次打开时，工作台复用同一事项并补齐缺失的初始文件，保留你改过的文件、组织和仓库关联，以及已发布的版本。演示需要产品经理、研发经理和测试经理三个内置岗位。使用 `PA_DB_PATH` 时，演示保存在数据库同级的 `inner-matter/`。内存数据库模式下没有这个入口。

维护者可用[内置演示验证记录](../validation/runtime-checks.md#2026-11-16-内置演示四步实机验证)复跑脚本并定位代码。

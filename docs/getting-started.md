# 安装与首次运行

按本文启动本地工作台，再用虚构的反馈收集场景完成一次需求讨论。所有项目命令都在源码或解压包的根目录运行。

## 1. 准备环境

先检查已有工具。

```bash
node --version
npm --version
git --version
```

项目要求 Node.js 22.19 或更高版本。各平台的验证结果见[发布说明](releases/v0.6.1.md)。

从 [0.6.1 发布页](https://github.com/civaapple-alt/personal-agent/releases/tag/v0.6.1)下载源码包或预构建包。也可以克隆该版本的源码。

```bash
git clone --branch v0.6.1 https://github.com/civaapple-alt/personal-agent.git
cd personal-agent
```

## 2. 安装本地 Pi CLI 并配置模型

AI 岗位通过本机 Pi CLI 调用模型和工具。请先安装 Pi，再配置模型访问权限。安装命令见 [Pi 官网](https://pi.dev/)。

按系统和包管理方式选择安装入口。

| 环境 | 官方安装入口 |
| --- | --- |
| macOS、Linux | 官网的 curl 安装方式 |
| Windows | 官网的 PowerShell 安装方式 |
| 使用 Node 包管理器 | 官网的 npm、pnpm 或 bun 安装方式 |

在准备启动工作台的终端确认 `pi` 已加入 `PATH`。

```bash
pi --version
```

打开 Pi 的交互界面。

```bash
pi
```

复现已验证的 Pi 1.5.2 环境时，可安装 `@earendil-works/pi-coding-agent@1.5.2`。日常安装和更新见 [Pi 官方文档](https://docs.pi.dev/latest)。

在 Pi 中用 `/login` 配置模型访问，再用 `/model` 确认可用模型。把认证信息保存在 Pi 的配置中。

内置岗位默认使用 `kimi-coding / kimi-for-coding`。每个岗位按自己的 provider 和 model 设置运行。使用其他提供商时，先[修改参与岗位的模型](user-guide.md#调整岗位模型)，再派发任务。调用费用和额度以所用提供商为准。

如果服务先于 Pi 启动，退出服务，再从能执行 `pi --version` 的终端重新启动。

## 3. 安装项目依赖并启动工作台

从源码运行时，先安装依赖，再选择个人或团队模式。

```bash
npm ci
```

### 方式 A：本机单人快速试用（默认）

```bash
npm run start:web
```

终端显示监听地址后，打开 `http://127.0.0.1:4310`。本机默认以「本机所有者」身份免密进入。点击左下角的「切换账号」可打开登录或注册页。

### 方式 B：多人团队共享服务（推荐开启权限控制）

```bash
PA_REQUIRE_AUTH=1 PA_HOST=0.0.0.0 PORT=4310 npm run start:web
```

首次打开网页时，在「初始化超级管理员账号」填写名称、邮箱和至少 8 位密码。自动化部署也可用 `PA_ADMIN_EMAIL` 和 `PA_ADMIN_PASSWORD` 初始化。

注册默认采用 `open_review`。新同事注册后，由超级管理员进入「超管控制台 → 用户审核与配额」审核账号。组织、配额和邀请的操作步骤见[团队协作指南](user-guide.md#团队账号超级管理员与组织协作)。

用 `PA_WORKSPACES_ROOT` 指定团队 Git 克隆目录，默认是 `<dataDir>/team-workspaces`。对外开放时，通过 HTTPS 反向代理访问。部署边界见[安全说明](../SECURITY.md)。

### 从个人本机试用切换到团队共享部署

1. 保持原数据库路径，再按方式 B 启动。新版本会迁移现有数据库，保留组织、工作区、事项、成果、经验和会话关联。
2. 如果尚未设置密码，在首次访问时初始化超管账号。系统沿用占位账号 `usr_local_owner` 的 ID 及其组织身份。已设密码时，直接用原账号登录。团队模式下，本机回环访问也需要登录。
3. 在「超管控制台 → 平台安全边界」复查注册策略、克隆主目录、本地目录白名单和命令型预览。默认设置允许本地目录绑定和命令型预览。团队成员之间有信任边界时，关闭命令型预览。
4. 在「我的团队」新建业务组织，再给同事发送该组织的邀请链接。试用时登记的仓库和事项通常仍在默认组织。可将默认组织里的仓库设为「受限」，或将事项设为「私密」。
5. 迁往另一台服务器时，先停服并复制完整 `.data/`，再核对目标机上的仓库路径。另开一份独立数据库时，使用新的 `PA_DB_PATH`。

旧局域网口令仍可加入协作，AI 派发使用正式账号。长期共享时使用邮箱账号和组织邀请。

如果使用预构建包，在解压目录直接启动。团队模式同样通过环境变量配置。

```bash
node dist/server/main.js
```

预构建包也不包含 Pi，执行 AI 任务仍需要上一步的本地安装与模型配置。

两种方式默认都使用当前目录的 `.data/`。启动和浏览工作台可以验证页面是否可用。发送演示提问时才调用模型。服务在前台运行，按 `Ctrl+C` 退出。

## 4. 发起第一次需求讨论

1. 以本机所有者身份进入新建事项，点击**体验内置演示**。
2. 确认出现“小团队反馈收集盒”和四步引导。此时只准备了虚构资料，尚无 AI 产出。
3. 在“需求讨论”中填入提问，阅读输入内容，再发送给产品经理。这一步开始使用模型。
4. 等待产品经理概括用户问题并提出关键问题。第一轮只讨论需求，成果库不应因此新增正式版本。

首次发送前确认当前关联的是内置演示工作区。它默认位于 `.data/inner-matter`，是独立 Git 仓库，但不是沙箱。继续专业协作、V1 和 V2 的步骤见[四步演示说明](inner-matter-demo.md)。

要验证本地服务启动，在源码目录运行以下命令。

```bash
npm run build
npm run check:startup
```

启动检查用临时数据和端口验证两个服务入口。使用真实模型的演示命令见 [demo 导航](../src/demo/README.md)。

## 5. 处理常见启动问题

| 现象 | 处理方式 |
| --- | --- |
| Node 不支持 TS 或 `node:sqlite` | 核对 `node --version` 与终端实际 PATH；换到满足要求的 Node 后重新安装依赖 |
| 端口 4310 已被占用 | 退出旧实例，或用 `PORT=4311 npm run start:web`；访问对应的新端口 |
| 网页可打开，派发时报找不到 Pi | 在启动服务的同一个终端确认 `pi --version`，再重启服务 |
| 提供商、模型或认证报错 | 对照岗位 provider/model 与 Pi 的认证；不要仅在 Pi 中切换模型后重试 |
| 缺少 Skill、扩展或 MCP 工具 | 核对角色能力报告与实际配置；导入模板不会自动安装依赖 |
| 问：初始管理员默认账号/密码是多少？ | 本项目不预设固定默认密码。`PA_REQUIRE_AUTH=1` 首次访问网页由你现场设置初始超管邮箱与密码（或用 `PA_ADMIN_EMAIL`/`PA_ADMIN_PASSWORD` 初始化）；默认免密回环下的占位账号没有登录密码 |
| 注册后提示「账号待超级管理员审核」 | 超管在 `#/admin → 平台安全边界` 开启了「管理员审核」；由超管前往 **超管控制台 → 用户审核与配额** 点「审核通过」并保存后点「刷新审核状态」即可进入 |
| 同浏览器打开组织邀请链接仍显示原账号 | 浏览器保留了原账号登录 Cookie，工作台会弹出「当前浏览器已登录某某」提示窗，点击 **「退出并注册新成员」** 即可切换为新用户注册；自测新成员也建议使用无痕窗口 |
| 保存的会话文件损坏或丢失 | 停止该事项，保留报错并按备份恢复对应文件；当前没有一键重置入口 |

数据备份、局域网协作及模型开销见[使用指南](user-guide.md)，环境参数见[配置参考](configuration.md)。

# 安装与首次运行

按本文启动本地工作台，再用虚构的反馈收集场景完成一次需求讨论。所有项目命令都在源码或解压包的根目录运行。

## 1. 准备环境

检查已有工具：

```bash
node --version
npm --version
git --version
```

项目要求 Node.js ≥ 22.19。当前开发验证使用 macOS、Node 26.10.0 和 Pi 1.5.2；Node 最低版本声明不代表所有系统和版本组合均已验证。

从 [0.6.0 发布页](https://github.com/civaapple-alt/personal-agent/releases/tag/v0.6.0)下载源码包或预构建包。也可以克隆该版本的源码。

```bash
git clone --branch v0.6.0 https://github.com/civaapple-alt/personal-agent.git
cd personal-agent
```

## 2. 安装本地 Pi CLI 并配置模型

**本地 Pi CLI 是必需的 AI 执行依赖。** 它负责本项目成员的模型与工具循环，不是可选插件，也不能只填一个模型 API 密钥就跳过。Pi 的产品说明与多平台安装以 [pi.dev](https://pi.dev/) 为准，本项目不自动安装 Pi。

先在官网选择与你的系统和包管理方式对应的安装入口：

| 环境 | 官方安装入口 |
| --- | --- |
| macOS、Linux | 官网的 curl 安装方式 |
| Windows | 官网的 PowerShell 安装方式 |
| 使用 Node 包管理器 | 官网的 npm、pnpm 或 bun 安装方式 |

Personal Agent 的离线验证涵盖 macOS 本机检查和仓库的 GitHub Actions 检查。具体平台和运行结果见[发布说明](releases/v0.6.0.md)。

安装后在将用于启动工作台的终端检查，确认 `pi` 已在 `PATH` 中。已有可用安装时不必重复安装：

```bash
pi --version
```

再启动 Pi，按 [Pi 官方文档](https://docs.pi.dev/latest)完成认证：

```bash
pi
```

当前项目已验证 Pi 1.5.2，不将它写成唯一允许安装的版本，也不保证尚未验证的其他版本兼容。复现该基线时可显式安装 `@earendil-works/pi-coding-agent@1.5.2`；日常安装和更新优先遵循官方指引。

在 Pi 交互界面使用 `/login` 配置模型访问，并用 `/model` 确认可用模型。认证由 Pi 管理，不要把 API 密钥写入角色 Markdown、项目文档或问题报告。

**内置岗位默认使用 `kimi-coding / kimi-for-coding`。** Pi 中选择过其他模型，不会自动覆盖本项目岗位的 provider/model 配置。若使用其他提供商，先按[调整岗位模型](user-guide.md#调整岗位模型)修改参与成员，再派发任务。模型调用是否收费、订阅额度及限额以所用提供商为准，本项目不附送模型额度。

如果安装 Pi 前已经启动服务，退出后从能执行 `pi --version` 的终端重新启动。此时网页能打开仍不代表模型认证、工具或 Skills 已可用。

## 3. 安装项目依赖并启动工作台

从源码安装依赖后，可按使用场景选择启动方式：

### 方式 A：本机单人快速试用（默认）

```bash
npm ci
npm run start:web
```

终端显示监听地址后，打开 `http://127.0.0.1:4310`。本机 `127.0.0.1` 默认免密码直接进入（左下角显示 `本机所有者` 与「切换账号」按钮），方便快速体验内置演示与本地项目；若只需切换账号测试，也可以直接点「切换账号」打开登录/注册页。

### 方式 B：多人团队共享服务（推荐开启权限控制）

```bash
PA_REQUIRE_AUTH=1 PA_HOST=0.0.0.0 PORT=4310 npm run start:web
```

- **没有默认/硬编码管理员密码**：首次开启 `PA_REQUIRE_AUTH=1` 访问网页时，会自动出现 **「初始化超级管理员账号」** 表单，由你当场填写管理员名称、邮箱和 ≥ 8 位密码（若用于自动化部署，也可启动前设置 `PA_ADMIN_EMAIL` 与 `PA_ADMIN_PASSWORD` 环境变量免界面初始化）。
- **新注册账号默认需要超管审核**：`registrationMode` 默认为 `open_review`（开放注册、管理员审核）；新同事通过邮箱密码注册后，需由超级管理员在 `#/admin → 用户审核与配额` 点击「审核通过」并确认配额方可使用工作台。
- 建议同时通过 `PA_WORKSPACES_ROOT` 指定团队 Git 克隆主目录（默认 `<dataDir>/team-workspaces`）；对外暴露或经反向代理访问时，必须配合 HTTPS/TLS 使用，安全细则见[安全说明](../SECURITY.md)。
- 注册审核模式、成员配额、组织创建与 `?invite=orginv_...` 邀请步骤见[使用指南 · 团队账号、超级管理员与组织协作](user-guide.md#团队账号超级管理员与组织协作)。

### 从个人本机试用切换到团队共享部署

如果先前先按**方式 A**在本机免密试用，之后改用**方式 B**（`PA_REQUIRE_AUTH=1 PA_HOST=0.0.0.0 ...`）启动：

1. **同一台机器、同一数据库支持原地兼容衔接**：
   - 继续使用同一份 `.data/personal-agent.db`（或同一个 `PA_DB_PATH`）时，库表结构幂等增量升级；免密试用期建立的工作区、事项、交付物、成员记忆与 Pi 会话都会保留。
   - 若试用阶段尚未给管理员设置过密码，首次开启 `PA_REQUIRE_AUTH=1` 访问网页会弹出 **「初始化超级管理员账号」**（或由 `PA_ADMIN_EMAIL`/`PA_ADMIN_PASSWORD` 自动初始化），系统会**原地更新**占位超级管理员 `usr_local_owner`（保留原 ID 不变），原有默认组织的所有者（`org_owner`）身份与历史事项归属不断裂。
   - 若试用阶段已通过「切换账号」设置过管理员密码，重启后不会再弹出初始化页，直接出现登录页用该账号密码登录即可。
2. **本机回环免密失效与安全边界复查**：
   - 开启 `PA_REQUIRE_AUTH=1` 后，本机 `127.0.0.1` 不再自动免登录进入。
   - 平台默认注册模式为**管理员审核（`open_review`）**；为开箱方便，平台设置仍默认允许本地目录绑定（`allowLocalWorkspacePath: true`）和命令型预览（`allowCommandPreviews: true`）。切到多成员共享服务后，建议超级管理员第一时间进入 **超管控制台（`#/admin`）→「平台安全边界」** 复查注册策略、按需关闭本地目录绑定或配置白名单前缀、确认 `workspacesRoot`，并在非全可信环境关闭命令型预览。
3. **隔离试用期的默认组织数据**：
   - 免密试用期自动登记的 `personal-agent` 仓库、手动绑定的本地仓库和默认发起的事项，通常归在「默认组织」下且默认可见性为组织内可见（`org`）。
   - 如果不想让新加入的团队成员看到本机试用期仓库与测试事项：**建议在「我的团队」为团队业务新建独立组织，并仅分发新组织的 `?invite=orginv_...` 邀请链接**（不要直接邀请同事进默认组织），或按需将默认组织内的敏感仓库/事项设为 `restricted`（受限成员可见）/ `private`（私密）。
4. **跨机器迁移、旧口令兼容与净库重开**：
   - 如从个人电脑迁移到另一台共享服务器，先停服再整体拷贝 `.data/`（含数据库、`uploads/`、`pi-sessions/`），并确保原本地绑定仓库（`local`）在目标机相同路径下存在（或改为通过 Git Clone 在组织下重新克隆）；若不希望保留个人试用历史，改用全新的 `PA_DB_PATH` 启动即可。
   - 原有旧版局域网协同口令（`legacy_token`）仍保留向后兼容识别且不可直接触发 AI；团队长期共享协作建议统一切换为邮箱账号与组织邀请链接。

如果拿到的是预构建包，在解压目录运行以下命令（可同样前置 `PA_REQUIRE_AUTH=1` 等环境变量），无须先安装 npm 依赖或重新构建：

```bash
node dist/server/main.js
```

预构建包也不包含 Pi，执行 AI 任务仍需要上一步的本地安装与模型配置。

这两种方式都会使用所在目录的运行数据。启动、浏览、打开内置演示不会发起模型请求。不要为了修复启动问题而删除已有 `.data/`。服务保持在前台运行，按 `Ctrl+C` 退出。

## 4. 发起第一次需求讨论

1. 以本机所有者身份进入新建事项，点击**体验内置演示**。
2. 确认出现“小团队反馈收集盒”和四步引导。此时只准备了虚构资料，尚无 AI 产出。
3. 在“需求讨论”中填入提问，阅读输入内容，再发送给产品经理。这一步开始使用模型。
4. 等待产品经理概括用户问题并提出关键问题。第一轮只讨论需求，成果库不应因此新增正式版本。

首次发送前确认当前关联的是内置演示工作区。它默认位于 `.data/inner-matter`，是独立 Git 仓库，但不是沙箱。继续专业协作、V1 和 V2 的步骤见[四步演示说明](inner-matter-demo.md)。

想先验证安装而不调用模型，可从源码目录运行：

```bash
npm run build
npm run check:startup
```

检查使用临时数据和端口，验证源码及构建入口，不代替 AI 协作验证。`demo:*` 真实任务命令另见 [demo 导航](../src/demo/README.md)，不要将其当作免费录播。

## 5. 处理常见启动问题

| 现象 | 处理方式 |
| --- | --- |
| Node 不支持 TS 或 `node:sqlite` | 核对 `node --version` 与终端实际 PATH；换到满足要求的 Node 后重新安装依赖 |
| 端口 4310 已被占用 | 退出旧实例，或用 `PORT=4311 npm run start:web`；访问对应的新端口 |
| 网页可打开，派发时报找不到 Pi | 在启动服务的同一个终端确认 `pi --version`，再重启服务 |
| 提供商、模型或认证报错 | 对照岗位 provider/model 与 Pi 的认证；不要仅在 Pi 中切换模型后重试 |
| 缺少 Skill、扩展或 MCP 工具 | 核对角色能力报告与实际配置；导入模板不会自动安装依赖 |
| 问：初始管理员默认账号/密码是多少？ | 本项目不预设固定默认密码。`PA_REQUIRE_AUTH=1` 首次访问网页由你现场设置初始超管邮箱与密码（或用 `PA_ADMIN_EMAIL`/`PA_ADMIN_PASSWORD` 初始化）；默认免密回环下的占位账号没有登录密码 |
| 注册后提示「账号待超级管理员审核」 | 超管在 `#/admin → 平台安全边界` 开启了「管理员审核」；由超管前往 **超管控制台 → 用户审核与配额** 点「审核通过」并保存后点「刷新审核状态」即可进入 |
| 同浏览器打开组织邀请链接仍显示原账号 | 浏览器保留了原账号登录 Cookie，工作台会弹出「当前浏览器已登录某某」提示窗，点击 **「退出并注册新成员」** 即可切换为新用户注册；自测新成员也建议使用无痕窗口 |
| 保存的会话文件损坏或丢失 | 停止该事项，保留报错并按备份恢复对应文件；当前没有一键重置入口 |

数据备份、局域网协作及模型开销见[使用指南](user-guide.md)，环境参数见[配置参考](configuration.md)。
